# Alertmanager Jev Triage

Install the live TLS dependency / Installez la dépendance TLS pour l'usage réel / Instale la dependencia TLS para uso real: `python3 -m pip install -r requirements.txt`.

## English

An authenticated relay for [Prometheus Alertmanager webhooks](https://prometheus.io/docs/alerting/latest/configuration/). It forwards every original alert group to a configured JSON webhook and adds `jevDecision` with a stable digest, versioned finite choice, outcome, and probability. The decision is `incident`, `routine`, or `review`. It never silences, inhibits, resolves, or drops an alert. A Jev failure is forwarded as `review`; a failed downstream delivery returns HTTP 503 so Alertmanager can retry. Resolved groups skip Jev. Truncated groups and groups with more than ten alerts go to review. SQLite caches successful Jev decisions, while every notification is forwarded.

Offline: `python3 triage.py --demo` and `python3 -m unittest discover -s tests -v`. For live use, set `TYPESAFE_API_KEY`, `ALERTMANAGER_WEBHOOK_TOKEN` (random, at least 16 characters), `JEV_DOWNSTREAM_URL`, and optionally `JEV_DOWNSTREAM_TOKEN` privately, then run `python3 triage.py --serve`. Configure Alertmanager's generic webhook receiver for `http://127.0.0.1:8095/webhook` and its `http_config.authorization.credentials_file` with the bearer token, or place the relay behind an authenticated HTTPS ingress. The downstream URL must use HTTPS or localhost HTTP. Alert annotations can contain sensitive text and selected descriptions are sent to Jev. Keep the downstream idempotent using `jevDecision.id`, because retries can repeat delivery. The Jev API was exercised with synthetic input; no live Alertmanager instance was available.

## Español

Repetidor autenticado para los [webhooks de Prometheus Alertmanager](https://prometheus.io/docs/alerting/latest/configuration/). Reenvía cada grupo original de alertas a un webhook JSON configurado y añade `jevDecision`: huella estable, elección acotada y versionada, resultado y probabilidad. El resultado es `incident`, `routine` o `review`. Nunca silencia, inhibe, resuelve ni elimina alertas. Un fallo de Jev se reenvía como `review`; un fallo del destino devuelve HTTP 503 para permitir un reintento. Los grupos resueltos no usan Jev. Los grupos truncados o de más de diez alertas pasan a revisión. SQLite almacena las decisiones Jev correctas, mientras cada notificación se reenvía.

Sin conexión: `python3 triage.py --demo` y `python3 -m unittest discover -s tests -v`. Para uso real, defina en privado `TYPESAFE_API_KEY`, `ALERTMANAGER_WEBHOOK_TOKEN` (aleatorio, al menos 16 caracteres), `JEV_DOWNSTREAM_URL` y opcionalmente `JEV_DOWNSTREAM_TOKEN`, y ejecute `python3 triage.py --serve`. Configure el receptor webhook genérico de Alertmanager para `http://127.0.0.1:8095/webhook` y `http_config.authorization.credentials_file` con el token Bearer, o coloque el repetidor detrás de una entrada HTTPS autenticada. El destino debe usar HTTPS o HTTP local. Las anotaciones pueden contener texto sensible y las descripciones seleccionadas se envían a Jev. El destino debe deduplicar con `jevDecision.id`, pues los reintentos pueden repetir la entrega. La API Jev se probó con datos sintéticos; no había una instancia Alertmanager real disponible.
